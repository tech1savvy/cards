# Amazon S3

- *Amazon S3* is *object storage with usage-based billing*, replicated across multiple *Availability* Zones. Best for static assets and backups.

## Properties
- S3 stores data as objects within *buckets*.
- An **object** consists of a file and optionally any **metadata** that describes that file.
- A **key** is a unique identifier for an object within a bucket.
- Storage capacity is virtually *unlimited*.

# S3 Fundamentals

- A *bucket* is the fundamental container for data in Amazon S3. You cannot upload an object without first creating a bucket.

- S3 objects consist of *data plus metadata*. The Object Key is the unique identifier (name) for an object within a bucket.

- An Object Key in S3 is the *unique identifier (name)* for an object within a bucket. URL structure: `http://[bucket-name].s3.amazonaws.com/[object-key]`

- Individual S3 objects can be up to *5 TB*, with an *unlimited* number of objects.

- S3 buckets must be *globally unique* across all AWS accounts and *DNS compliant* (no spaces, no special characters).

- An S3 bucket's geographical location is determined by the *Region* you choose. Data is *redundantly stored across multiple facilities within that Region*.

- Everything in S3 is *private by default*. Block Public Access is a bucket-level safety setting to prevent accidental exposure. IAM Policies and S3 Bucket Policies control permissions.

# S3 Storage Classes

| Storage Class        | Access Pattern                   | Key Idea                               |
| -------------------- | -------------------------------- | -------------------------------------- |
| S3 Standard          | *1;;Frequent access*             | *2;;General-purpose storage*           |
| Intelligent-Tiering  | *1;;Unknown access*              | *2;;Auto moves between tiers*          |
| Standard-IA          | *1;;Infrequent access*           | *2;;Lower storage cost, retrieval fee* |
| One Zone-IA          | *1;;Infrequent*                  | *2;;Stored in single AZ*               |
| Glacier Instant      | *1;;Archive, quick retrieval*    | *2;;Millisecond restore*               |
| Glacier Flexible     | *1;;Archive*                     | *2;;Minutes–hours retrieval*           |
| Glacier Deep Archive | *1;;Long-term archive (7-10 yr)* | *2;;Lowest cost, ~12 hr retrieval*     |

- All S3 Storage Classes maintain *11* nines durability.

# Individual Storage Classes

- S3 Standard is *general-purpose storage for frequently accessed data*, providing 11 nines durability.

- S3 Standard-IA has *lower storage cost but comes with a retrieval fee*. Useful for data accessed less frequently but needing rapid access when needed.

- S3 One Zone-IA is an *infrequent access tier stored in a single Availability Zone*, with lower cost than Standard-IA but less resilient.

- S3 Intelligent-Tiering *automatically moves objects between tiers based on changing access patterns*, optimizing cost for unknown or unpredictable access.

- S3 Glacier Instant Retrieval is *archive storage with millisecond restore times*, for archival data that needs immediate retrieval.

- S3 Glacier Flexible Retrieval is *archive storage with retrieval times from minutes to hours*, balancing cost and access speed for archival data.

- S3 Glacier Deep Archive is *lowest-cost storage for long-term archive (7-10 years)*, with retrieval taking ~12 hours.

# S3 Versioning

What does S3 Versioning do?
***
Allows you to keep **multiple versions** of an object in the **same bucket**. Guards against accidental deletions or overwrites. Deleting an object adds a **delete marker** instead of removing it permanently. States: **Unversioned** (default), Versioning-enabled, Versioning-suspended.

# S3 Encryption

- How does encryption at rest work in S3?::**At Rest**: Server-side encryption (AWS handles it) or Client-side encryption (you handle it before upload).

- How does encryption in transit work in S3?::**In Transit**: Via SSL/TLS.

# S3 Lifecycle Management

What is S3 Lifecycle Management?
***
Automates object storage management.

Actions:

**Transition** — Move objects to cheaper storage classes over time. Example: Standard → Standard-IA → Glacier.

**Expiration** — Automatically delete objects after a defined period. Example: Delete logs after 365 days.

# Lifecycle Transition Actions

- Transition Actions *move objects to a cheaper storage class after a specified number of days*. Example: Standard → Standard-IA → Glacier.

# Lifecycle Expiration Actions

- Expiration Actions *permanently delete objects after a specified number of days* (e.g., logs).

# S3 Cross-Region Replication (CRR)

What is Cross-Region Replication (CRR) in S3?
***
Automatically copies objects to a bucket in another **AWS Region**.

Replicates:
- objects
- metadata
- tags

Use cases:
- regulatory compliance
- geographic redundancy
- lower latency for global users
- cross-account data protection
